# Round five: record

## Fixed before the run (2026-10-04, before any code change)

These rules were written down before any round-five code was edited and are not changed after the run,
whatever it shows. The round-four record of what happens when rules are changed after seeing a result is
`report/round_four_results.md`.

- **Precision floor:** `MIN_PRECISION = 0.96` (`src/train.py`), unchanged from round four. The threshold is
  the lowest decision value that keeps 96% precision on the out-of-fold originals of the grouped folds.
- **Champion:** the round-four model, run by its own code in `backup_round4/` (a subprocess), verdicts
  computed fresh (the round-three verdict cache was moved into `backup_round4/report/`).
- **Gate groups and rule:** `TOLERANCE = 1`. Three groups, every one must pass:
  1. POOLED = official_dev + handwritten_dev + handwritten_dev3: total mistakes not above the champion's,
     neither false alarms nor missed attacks above the champion's by more than 1.
  2. RECENT = hand-written set 4 + agent-drafted set 5 (development data since their mistakes were read):
     the same rule.
  3. probe_dev: the same, and missed attacks strictly lower.
- **Champion bar** (round four on these sets, from `report/train_log.txt` and `report/set5_scored.csv`,
  false alarms / missed attacks): official_dev 0 / 1, handwritten_dev 5 / 3, handwritten_dev3 2 / 3,
  POOLED 7 / 7; set 4 3 / 7, set 5 4 / 13, RECENT 7 / 20; probe_dev 12 / 24. A candidate therefore needs:
  POOLED total <= 14 with false alarms <= 8 and misses <= 8; RECENT total <= 27 with false alarms <= 8 and
  misses <= 21; probe total <= 36 with false alarms <= 13 and misses <= 23. The gate recomputes the
  champion's counts; if they differ from these by more than one text, the subprocess did not run the
  round-four model and the run is repeated after the cause is fixed.
- **Candidates:** `emb+rules20` first, then `emb+rules16`; the first that passes is promoted.
- **A fail by one text is a fail.** No candidate passing means round four stays, the test sets are not
  scored, and the floor, tolerance and groups are not revisited.
- **Test sets, scored once by the final run if a candidate passes:** the official final part, deepset,
  jackhhao, gandalf, and the test splits of the three new sources (oasst1, injecagent, bipia). The six
  round-four source splits are development data from now on (reported, never gating). Set 6 is scored once,
  after promotion, by `scripts/score_set.py`; until then no agent or script opens it.
- **What round five changes:** three data sources (oasst1 benign prompts, capped per language; InjecAgent
  tool-output attacks with clean twins; BIPIA clean documents with manipulative insertions) and two rule
  fixes (`dangerous_action_count`: `DELETE FROM`, `truncate ... tables`, paths in remove orders,
  bucket/snapshot purges; `tool_action_count`: mass-messaging orders, `.example` addresses). Nothing else
  in the scoring code changes.

## Rule fixes (2026-10-04, before the run)

- `dangerous_action_count`: the clause splitter removes the `;` that the old `delete from ... ;` pattern
  required, so it never matched inside a clause; now `delete from <table> [where ...]` matches at the
  clause end. Added "truncate the ... tables" in words, a path before the noun in remove orders
  ("remove the entire /var/app/data directory"), and bucket or snapshot purges.
- `tool_action_count`: mass-messaging orders ("message every one of them", "text everyone in my address
  book") count on their own, without secrecy, private-data or address evidence; `.example`, `.test`,
  `.invalid` and `localhost` count as addresses. "message", "text", "dm", "ping", "contact", "spam",
  "access", "export", "download" and "connect" now start an order clause.
- Self-check sentences added for both; the harmless-corpus rates stayed at 0.00%.

### Diagnosis (development data only; the decision above stands)

The rejected `emb+rules20` candidate at other thresholds, scored with the round-five rules it was trained
with (champion: POOLED 7 / 7, RECENT 7 / 20, probe 12 / 24):

| threshold | POOLED fa / missed | RECENT fa / missed | probe fa / missed | would pass |
|---|---|---|---|---|
| 0.548 | 8 / 7 | 8 / 14 | 20 / 20 | no |
| 0.600 | 7 / 7 | 8 / 14 | 17 / 22 | no |
| 0.700 | 7 / 7 | 8 / 14 | 15 / 24 | no |
| 0.800 | 7 / 7 | 7 / 14 | 14 / 27 | no |
| 0.852 | 6 / 8 | 7 / 14 | 13 / 27 | no |

So the probe loss is not a threshold artefact: at every operating point the candidate makes at least 40
probe mistakes against round four's 36, with the extra ones in the command, correspondence and
multilingual slices (at 0.852: command 9 vs 8, correspondence 10 vs 9, multilingual 8 vs 6, embedded_human
11 vs 11, topic_switch 2 vs 2). The gains are real and where the data aimed: set 5 misses 13 -> 8 (all
three destructive commands, one more send order, one more task switch caught), set 4 7 -> 6, POOLED equal.
What changed at once: 2,281 new training rows (1,500 of them benign oasst1 prompts), two rule fixes, and
the grid's move to C = 1 with rule weight 2.0; the run cannot say which of the three cost the probe set.
